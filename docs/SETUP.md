# Setup / Install / Build / Run

Tested on Windows 10/11 with PowerShell and Python 3.11. Commands below are
PowerShell; Linux/macOS equivalents are noted where they differ.

## 1. Prerequisites

- Python 3.11+ on your PATH (`python --version`)
- No API keys, no database, no Docker, no Node.js required.

## 2. Create an isolated virtual environment

From the project root (the folder containing this `docs/` directory):

```powershell
python -m venv .venv
```

Linux/macOS: `python3 -m venv .venv`

## 3. Activate it and install pinned dependencies

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux/macOS: `source .venv/bin/activate`

(If you'd rather not activate, every command below also works by calling
`.\.venv\Scripts\python.exe` directly instead of `python`.)

## 4. Run the orchestrator against a scenario

Each scenario lives in `scenarios/<name>/requirement.md`. Running one drives
the full Requirements -> Design -> Implementation -> Testing/Documentation ->
Release Readiness pipeline and writes/evolves the code under `url_shortener/`.

```powershell
python -m orchestrator.cli run scenarios\01_greenfield_build_shortener
python -m orchestrator.cli run scenarios\02_brownfield_alias_and_ttl
python -m orchestrator.cli run scenarios\03_ambiguous_make_it_reliable
```

Run them **in that order** the first time -- Scenario 2 and 3 evolve the
codebase Scenario 1 creates (they are not independent).

Each run prints a live metrics summary and writes:

- `scenarios/<name>/run_log/audit.jsonl` -- full structured audit trail
- `scenarios/<name>/run_log/context.json` -- the final run state (decision lineage, approvals, etc.)
- `scenarios/<name>/run_log/summary.md` -- a human-readable run report

To replay the audit timeline + metrics for a scenario you've already run:

```powershell
python -m orchestrator.cli show-run scenarios\01_greenfield_build_shortener
```

To see real interactive human-approval prompts instead of auto-approval:

```powershell
python -m orchestrator.cli run scenarios\03_ambiguous_make_it_reliable --interactive
```

(Re-running a scenario is safe -- it re-executes the same deterministic
agents against the current code state and appends to that scenario's audit
log.)

## 5. Run the product (URL shortener) locally

```powershell
cd url_shortener
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Then open:

- `http://127.0.0.1:8000/` -- the minimal web UI
- `http://127.0.0.1:8000/docs` -- interactive Swagger API reference
- `http://127.0.0.1:8000/api/health` -- liveness check (added by Scenario 3)

## 6. Run the tests

Product tests (generated by the orchestrator's Testing agent):

```powershell
cd url_shortener
..\.venv\Scripts\python.exe -m pytest tests -v
```

Orchestrator engine tests (hand-written, cover retry/rollback/fallback/replan/safe-stop mechanics):

```powershell
.\.venv\Scripts\python.exe -m pytest tests -v
```

(from the project root -- note this is a *different* `tests/` directory
than `url_shortener/tests/`.)

## 7. Starting over from a clean slate

To re-generate everything from scratch (e.g. to watch Scenario 1 build the
app from nothing again):

```powershell
Remove-Item -Recurse -Force url_shortener
Remove-Item -Recurse -Force scenarios\*\run_log
python -m orchestrator.cli run scenarios\01_greenfield_build_shortener
python -m orchestrator.cli run scenarios\02_brownfield_alias_and_ttl
python -m orchestrator.cli run scenarios\03_ambiguous_make_it_reliable
```
